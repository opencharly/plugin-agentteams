# 2026.269.2113 — fix(agentteams): replace the retired plugin.source: builtin and gate it in-repo

## Summary

Replace the retired `plugin.source: builtin` with the module ref in this candy, and make the repo's own manifest gate actually exercise it.

`opencharly/spec#163` retired the `source: builtin` sentinel — `plugin.source` is now `source: #GithubRef` (no default). A post-spec#163 charly hard-errors on the old value, so the repo's own `charly box validate` step could not fail on the change while it ran a pre-spec#163 pin (`v2026.238.1242`). This PR replaces the retired value, migrates the root schema to the post-spec#163 floor, and pins the repo's CI charly to a release that carries the retirement — making the repo's own gate fail-without / pass-with the change.

### The exact change

| file | before | after |
|---|---|---|
| `candy/plugin-agentteams/charly.yml` | `source: builtin` | `source: github.com/opencharly/plugin-agentteams/candy/plugin-agentteams` |
| `charly.yml` (root schema) | `version: 2026.232.0520` | `version: 2026.261.1747` (`charly migrate`) |
| `.github/workflows/deploy.yml` (CI charly pin) | `v2026.238.1242` | `v2026.269.0131` |

The new `source` is the candy's own Go module path of record (`head -1 candy/plugin-agentteams/go.mod` → `module github.com/opencharly/plugin-agentteams/candy/plugin-agentteams`). It is behaviour-bearing, not cosmetic: `charly/internal/pluginsgen/main.go:185-233` (`pluginModulePath` / `readPluginSource`) reads `plugin.source` as the compiled-in plugin's module path, and `charly/plugin_loader.go:1206-1264` skips `builtin` while serving the compiled-in provider for the external ref via the `originBuiltin` coexist-switch. The value therefore must name a resolvable module path — and it does:

```
$ go list -m -versions github.com/opencharly/plugin-agentteams/candy/plugin-agentteams
github.com/opencharly/plugin-agentteams/candy/plugin-agentteams v0.2026237.1414 v0.2026240.121 v0.2026242.502 v0.2026242.525
```

The root migration and the CI-pin bump are coupled: a `2026.261.1747` root is rejected by the old `v2026.238.1242` charly ("config newer than supported"), so the pin moves with the root.
